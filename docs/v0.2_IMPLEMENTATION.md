# v0.2 Implementation Plan

## Objective

Replace FireRed's one-path starter opening with an Asterra starter selection system while preserving the classic Kanto trio.

## Player flow

```text
Professor Lyra
      |
      v
Starter Chamber
      |
      v
Choose Generation
  |      |      |
 Gen I  Gen II  Gen III
  |      |      |
  +------v------+
         |
   Choose Partner
         |
         v
   Starter received
         |
         v
   Nova chooses
   counter-partner
         |
         v
   First Asterra route
```

## Data model

| Generation | Starter 1 | Starter 2 | Starter 3 |
|---|---|---|---|
| I | Bulbasaur | Charmander | Squirtle |
| II | Chikorita | Cyndaquil | Totodile |
| III | Treecko | Torchic | Mudkip |

The same structure should make it straightforward to add later generations without rewriting the selection logic.

## Important GBA constraint

The final output must remain a normal FireRed-compatible `.gba`. Menus, scripts, party changes and rival logic must execute entirely inside the ROM.

## Implementation order

1. Establish the project build environment/source tree.
2. Locate and replace the original Professor Oak starter script flow.
3. Add generation-selection menu/script.
4. Add generation-specific starter menu/script.
5. Give selected starter to the player.
6. Store the chosen starter/generation for later events.
7. Implement Nova's counter-selection logic.
8. Update the opening battle/script flow.
9. Test save/load and fresh-game progression.
10. Build a `.gba` and emulator-test it.

## Acceptance test

A new game must be able to reach the starter selection, choose any of the nine initial starters, receive exactly that Pokémon, trigger the intended Nova response, and continue normally into the first route.
